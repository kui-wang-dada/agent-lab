# ⚠️ _analysis/ 准确度警告（衍生品加锁）

> **本目录所有文件 = 衍生品（二手梳理 / AI 解析），不是客户原文件**。引用前必读。
>
> **为什么要加这把锁**：AI 对客户原型 / SRS / xlsx 的二手梳理里，
> **业务描述往往可信，但派生的"编号 / 索引 / 计数"经常错位**（页码顺序、表数、画布数等）。
> 把可信部分和坏掉的部分用一张表逐文件标清楚，比"全信"或"全删"都好。

---

## 逐文件可信度表（实例化后按真文件填）

| 文件 | 内容 | 准确性 | 怎么用 |
|---|---|---|---|
| `<衍生梳理1>.md` | <模块结构 / 业务字段 / IA 描述> | ✅ 业务描述可信，⚠️ **页码/idx 可能错位** | 按 name 引用，**不按 idx** |
| `<衍生索引>.csv` | <idx → name 映射> | ❌ **idx 顺序与真实 runtime 不一致** | idx 列**不可作外部引用键** |

| `<技术调研>.md` | <技术选型调研> | 🟡 与原型无关，独立可信 | 可引用 |

> 准确性图例：✅ 可信 / ⚠️ 部分可信（标清哪部分坏）/ ❌ 不可信（标清坏在哪）/ 🟡 与原型无关独立可信。

## 怎么用本目录的文档

✅ **可以引用**：
- 业务字段名（如客户用语命名的实体 / 状态）
- 状态机 / 流程描述
- 分组结构、Tab 结构（板块**内**的层级）

❌ **不要引用**：
- 任何 "page X / 第 N 屏" 的 idx 编号（衍生梳理里高频错位）
- "X 个画布 / Y 个页面" 的精确计数（以真实 runtime 为准）

## 该用什么替代（视觉/页码 ground-truth）

- **视觉对齐**：用**真截图**——不要用字段表当视觉依据（dongjiaoshan 教训：prompt 用字段表非真截图 → 视觉偏差返工）。
  截图来源按栈定（web 用浏览器自动截图 / 小程序用对应开发者工具 CLI 截图），存到 `../prototype/<...>/_real_screenshots/`。
- **page 引用**：用原型工具的**稳定 cid / 节点 id**，不用顺序 idx。
- **实施前核实**：UI ticket 的 §0 自检步骤包含"对照真截图"，不允许凭衍生梳理实现。

## 为什么不直接删 _analysis/

业务描述部分（字段名 / 状态机 / IA 分组）有价值，删了可惜。
坏的只是编号/索引系统，所以**加警告锁定使用规则**，而不是整删。
