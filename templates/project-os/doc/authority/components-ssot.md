## 3. 跨页面共享组件 / 范式识别（治"组件没识别"返工螺旋）

<!-- 为什么单列识别步骤：dongjiaoshan 的"选猪范式"——多个页面都要"搜耳号→筛选→选猪只"，-->
<!-- 但这个共享范式从没被识别成一个组件，于是 N 个页面各写一遍，改一次要改 N 处，触发 realign-sprint 返工。-->
<!-- 共享组件识别必须在 SP1 就做完（设计阶段），不是写到第 N 个页面才发现"诶这跟前面一样"。 -->

### 3.1 识别步骤（SP1 设计阶段强制跑一遍）

```
1. 把所有 UI 页面的真截图铺开（§2 表全部页面）。
2. 找"重复出现的视觉范式"：
   - 同样的列表+筛选+分页 → 抽一个列表组件
   - 同样的"选实体"交互（搜索→筛选→多选）→ 抽一个 Picker（如 dongjiaoshan 的"选猪"）
   - 同样的"录入表单"结构 → 抽一个 schema-driven 表单组件
   - 同样的 KPI 卡 / 趋势图 / 上传控件 → 各抽一个
3. 对每个识别出的范式：登记到 §4 共享组件清单 + 标注"哪些页面用它"。
4. 反向校验：§2 表里每个页面的"复用组件"列必须从 §4 清单里选，不能空着自由发挥。
```

> **为什么反向校验**：强制每个页面声明它复用哪些共享组件，等于在设计阶段就消灭"各写各的"——这是把"组件识别"从可选自觉变成 GATE 前的硬动作。

## 7. 按栈落地（视觉锚定怎么做 —— 栈是实例）

<!-- 设计原则：通用机制是"用真截图当 ground truth + 截图能现场补"；具体工具按栈选。 -->

| 栈 / 端 | 真截图怎么得到 | 设计→代码怎么对齐 |
|---|---|---|
| **web 端 `<<STACK_FRONTEND>>`** | 设计稿导出；或浏览器对真原型截图 | 用本栈的设计→代码映射机制把设计组件映射到代码组件；UI ticket 引该映射入口。详 `stacks/<<本栈>>-notes.md` §visual |
| **移动/小程序端 `<<STACK_APP>>`** | 用本栈对应工具的 CLI 截图（命令行起预览 + 截屏）；或对原型工具导出跑本地 server + 浏览器截图 | 截图 diff：实现页截屏 vs 真截图人工/工具比对（SP2 视觉自检环） |
| **原型工具导出（SPA 类）** | 起本地 `http.server` + 浏览器/Playwright 打开指定 screen/canvas → 等渲染完 → 截屏存档（编号接续） | 截图入 §2 表，UI ticket inline |

> **填表说明**：具体工具按本栈在 `stacks/<<本栈>>-notes.md` §visual 落地。
> （示例：web 端可用 Figma Code Connect 做设计→代码映射；小程序端可用微信开发者工具 CLI 截图——均为示例，按本栈落地。）

### 3.1（补截图 SOP，跨栈通用骨架）

```
1. 定位原型 screen/页面标识（查原型料的 page 名 → screen id 映射）。
2. 看 🥇 真截图目录有没有现成的：有 → 直接引用。
3. 没有 → 起原型运行环境（本地 server / 微信 CLI / Figma 导出）→ 打开对应屏 → 等完整渲染 → 截屏。
4. 存到 🥇 截图目录，编号接续；回填 §2 表对应行。
5. UI ticket prompt 里 inline 截图路径 + screen 标识，subagent 拿真原型而非文字描述。
```

> **注意**：Figma Code Connect / 微信开发者工具 CLI 等是**栈细节**，完整命令/配置写在 `stacks/<<stack>>-notes.md`，本表只给映射入口。
