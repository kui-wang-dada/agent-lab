# OQ — 开放问题表（待客户答 / 待决，每条必带 Fallback）

> 任何"客户没明确答、但实现需要的细节"进这里。
> **铁律：每条 OQ 必须有 Fallback**——让开发先按 Fallback 走，**不被这条问题卡住**。
> 批量推客户（如每周一次）拿答案；答了就把状态推进到 🟢 / ✅。
>
> **OQ vs CR 的分工**：OQ = "还不知道答案、先用 Fallback 顶着"；CR = "已经定了要改什么、有人签字"。
> OQ 拿到客户答 → 若需改实现，**升级成 CR**（在 [`changes.md`](changes.md) 开一条，互相引用）。

---

## 状态汇总

| 状态 | 含义 | 数量 |
|---|---|---|
| ⏳ Open | 待客户答，**先走 Fallback** | 0 |
| 🟢 Fallback adopted | 已采用 Fallback 实现，客户答可能微调 | 0 |
| ✅ Closed | 客户已答 / 已定，无悬念 | 0 |

> **状态机**：`⏳ Open` → （采用 Fallback 实现）→ `🟢 Fallback adopted` → （客户答 / 拍板）→ `✅ Closed`。
> 注意：⏳ 不代表"卡住"——⏳ 也已有 Fallback，只是还没开始按它实现。

## OQ 完整列表

| ID | 问题 | 影响 ticket | Due | 客户答 | Fallback（先行） | 状态 |
|---|---|---|---|---|---|---|
| OQ-1 | <一句话问题> | `<TICKET>` | D&lt;N&gt; 前 / M&lt;X&gt; 前 | _待答_ | **先按 &lt;X&gt; 做，留 config/flag 可调** | ⏳ |

> 上表第一行是占位示例，实例化后按真问题填。
> **Due 写法**：`D<N> 前`（某天前要答）/ `M<X> 前`（某里程碑前）/ `V2 启动前`（不阻塞 V1）。
> **不阻塞 V1 的 OQ** 也要写，但 Due 标到 V2，避免被当成"现在必须答"。

## 单条 OQ 详写模板（复杂问题表格放不下时，在下方追加详写段）

```
## OQ-NN: <问题标题>

- **提出人**：<Kevin / 客户 / Reviewer / AI>
- **影响 ticket**：<id1>, <id2>
- **提问日期**：YYYY-MM-DD
- **Due**：D<N> 前 / M<X> 前 / V2 启动前
- **客户答**：_待答_ / <客户答原文>
- **Fallback（先行）**：开发先按 <X> 做，<config / flag / 字段> 可改；若客户答 <Y> → <如何 hotfix>
- **状态**：⏳ Open / 🟢 Fallback adopted / ✅ Closed
- **关联 CR**：<拿到答案升级成 CR 后回填编号；无则省略>
```
