# D&lt;N&gt; Open Issues —— "卡住的"和"要拍板的"出口（只收两类）

> **本文件只收两类问题**：① 运行中**当场无法及时解决**的（需较大改动 / 涉上游 ticket / 跨域）；② **需决策**的（方案不明 / 要 Kevin 或客户拍板）。
>
> **人测/实施中能当场解决的问题，当场交 AI fix 闭环，不进本文件**（本文件不是 bug 跟踪器，是"卡住的"和"要拍板的"的出口）。
>
> **闭环：AI raise → 人原地填决策 → AI 批量执行。** 避免 AI 跑着跑着就去乱改别的文档。
>
> - AI 实施 ticket 时发现属于上述两类的问题 → 当场 append 到本文件，**不**当场改其他文档；能当场修的直接修，不 append。
> - 人（review/测试方）跑感官测试发现问题 → **能当场修的当场交 AI fix → 重测闭环**；只有属于上述两类的才 append，标编号 + 触发者。
> - **阻塞** raise（影响本 ticket 写不下去）→ 当场 STOP / 问人。
> - closing 时 AI 把待决条目编号汇总输出 → 请人在本文件「决策」字段**逐条原地填**（不用单独转出列表）。
> - AI 检测到决策已填 → 批量执行（doc / prompt / ADR / SSOT / 下游 ticket prompt）→ 把 status 改 ✅ + 补「落地」。
> - **人只填决策一行字**（a/b/c/拒绝/推后），不做"管家活"；AI 既是 raise 方又是执行方。
>
> **为什么这样设计**：人的 review/决策带宽是天花板。把"发现"与"执行"都压给 AI，人只在一个文件里做"判断"，把人力花在判断而非搬运上。能当场闭环的不进来，本文件只留真正卡住或要拍板的。

---

## 条目格式（每条一段，7 字段）

```markdown
### [<TICKET-ID>] <短标题>
- **类型**：设计模式缺陷 / 实现细节 / 业务理解偏差 / 待客户确认 / doc 漂移 / prompt 漂移 / 安全合规
- **严重程度**：S0 阻塞下游 / S1 影响 1 个 ticket / S2 仅本 ticket 内 cosmetic / S3 长尾优化
- **触发**：<一句话写清是怎么发现的；若来自感官测试，注明哪个 reviewer（A/B/C）>
- **影响范围**：<file:line 或下游 ticket id 列表>
- **建议方案**：<a/b/c 候选 + AI 推荐>（"待客户确认"类直接写"待 Kevin 问客户"）
- **状态**：⏳ 待决 / ✅ 已落地 / ❌ 拒绝 / 🟡 推下一版 / 🔵 推后续 ticket
- **决策**：⬜ <人 closing 时原地填：a / b / c / 拒绝 / 推后，可附 1-2 句理由>
- **落地**：⬜ <AI 执行后回填：commit hash 或 改动文件清单>
```

> **AI raise 时**：填到「决策」之前的字段，「决策」「落地」留 ⬜。
> **人 closing 时**：只动「决策」行。
> **AI 执行后**：把「状态」改 ✅、补「落地」。

## 类型说明

| 类型 | 含义 |
|---|---|
| **设计模式缺陷** | 跨 ticket 重复出现、本该设计期（SP1）拍板的架构问题（共享资源没定权威 / 基类没抽 / 命名两套） |
| **实现细节** | 单 ticket 范围内的代码细节 / 风格 / 命名 |
| **业务理解偏差** | AI 按 prompt 字面实现，但与客户原始材料 / 业务常识不符 |
| **待客户确认** | 业务规则不明，需 Kevin 问客户 |
| **doc 漂移** | 需求 / 架构 / schema / 变更记录之间不一致 |
| **prompt 漂移** | spawn prompt 字面与实际库 / SSOT / doc 不符 |
| **安全合规** | tenant 隔离 / 权限 / 支付 / 个人信息相关（一等公民，优先级单独抬） |

## 严重程度判断

- **S0**：本 ticket 实现完会让**下游 ticket 跑不通**（表/字段/接口路径/契约不对）或**安全漏洞** → closing 必修。
- **S1**：影响**当日另一个 ticket** 的实现路径（如共享资源 key 争议）→ closing 必决策。
- **S2**：仅本 ticket 内 cosmetic / 命名 / 注释 → 决策可推迟，先 ⏳。
- **S3**：长尾优化 / 下一版想法 → 一般决策 🟡 推下一版，不当晚改。
